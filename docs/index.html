A search query made of a photo and a short edit. A correct result has to show the same literal object as the photo, with the edit applied. A different chair in brown leather is wrong, and so is the same chair still in black. I built a two-stage retrieval system for this task and tested it on a public research benchmark of 1,883 search queries.

The task

Two questions for every candidate image

In instance-level composed image retrieval, each query pairs a reference photo with a text modification such as at night, as an emoji or with brown or dark beige leather. The benchmark is ICIR: 1,883 queries over 202 object instances, from furniture and products to cartoon characters, artworks and landmarks.

Each query is ranked against its own pool of correct images and carefully chosen near misses, not against random distractors. So every candidate has to pass two checks at once:

✓Same instance✕Edit applied

Wrong: right object, old state

The query chair again, still in black leather. Image similarity loves this candidate.

✕Same instance✓Edit applied

Wrong: right state, other object

A different lounge chair in brown leather. Text similarity loves this one.

✓Same instance✓Edit applied

Correct

The same chair, in brown leather. Only this one counts.

So the scores are multiplied, not added

Relevance here is a logical AND. With a sum, a strong score on one check can make up for failing the other, and both kinds of near miss survive. With a product, failing either check pulls the whole score down. Measured on the same centered SigLIP2 scores, the operator alone moves mAP@100 from 15.84 to 50.09.

The system

A fast first stage, then a second opinion on the top 100

The first stage scores every candidate in the query's pool with frozen SigLIP2 and keeps the top 100. A heavier verifier then rescores only that shortlist. Both stage-one scores stay in the final product, so the second stage adds evidence instead of replacing it. Two verifiers work: a cheap one trained on another dataset (Route A) and a large multimodal embedder guided by a description of the object (Route B).

Stage 1

Two corrections to a frozen model

Image centering. For a query of instance c, subtract the mean image embedding of every other instance, then compare. This removes dataset-wide directions (style, background, photo quality) that make different objects look alike.

Text contextualization. SigLIP's text tower was trained on captions, and "at night" is not a caption. The edit is wrapped in neutral caption fragments, before and after, and the embeddings are averaged. No answer information is added.

Route A

A probe trained elsewhere

A linear projection on frozen SigLIP1 features, trained on ILIAS, a separate instance-retrieval dataset. Swapping such a probe in for the image branch hurts: with SigLIP2, mAP@100 drops from 59.64 to 55.95. Used as one extra factor next to a matching text score, it reaches 66.05.

Route B, final

Point the big model at the object

An MLLM writes one line describing the query's object, with no mention of the edit. RzenEmbed-7B embeds each shortlisted candidate with that line as a guide:

Represent the candidate image for exact instance-level retrieval. Use the provided instance descriptor as an attention guide for the literal identity…

Without the descriptor the same model reaches 62.54. With it: 66.42.

Exact formula of the 66.42 run. The thesis describes the final score as the four-score product s¹ᵢ · s¹ₜ · sᴮᵢ · sᴮₜ. The run that produced 66.42 mAP@100 and 65.65 macro-mAP@100 also takes the square root of s¹ₜ and multiplies in a fifth factor: the square root of a SigLIP2 state score, the candidate's similarity to an MLLM-written caption of the target state minus 0.2 times its similarity to a caption of the source state.
score = s¹ᵢ · √s¹ₜ · sᴮᵢ · sᴮₜ · √(starget state − 0.2 · ssource state)
The plain four-score product scores 66.31 mAP@100 and 65.94 macro-mAP@100 on the same stored scores. The examples below use the 66.42 formula.

Probe

The instance information is already in the frozen embeddings

Route A rests on a finding about the representation itself. On ILIAS, an instance-retrieval dataset, I trained only a linear projection on top of frozen SigLIP2 features, holding out one whole domain each time and testing on it. To keep this affordable I cut ILIAS's distractor set to about one million images, chosen to keep the hard negatives.

Macro-mAP@100 over the eight held-out domains rose from 31.39 to 73.26. Every domain improved, including the ones the probe never saw in training.

A linear head cannot invent evidence the backbone does not encode, so the instance structure was there all along; raw cosine similarity just does not expose it. The catch is calibration: the probe sharpens the image side only, so on ICIR it works as an extra factor next to a text score, not as a replacement.

Lessons

What did not help, and where it still fails

The final system is short on purpose. These ideas were measured and left out.

Projection and query expansion

Both lowered SigLIP2's first stage. Directions that look like global noise can carry the small cues that tell two near-identical objects apart.

Min-score scaling

The benchmark's score normalization took the first stage from 59.64 down to 55.75 mAP@100.

Text centering

Centering the text side against external caption corpora did not improve the final SigLIP2 setting. A short edit has few repeated background-like directions to remove.

Richer generated text

Longer captions, rewrites and future-state captions from open MLLMs added variability to the text branch more often than evidence.

Grounding crops

Cropping candidates to the detected object (Grounding DINO) lost to whole images: many boxes were imperfect, and some identities live in scale and surroundings.

A bigger model as the first stage

RzenEmbed-7B alone ranks worse than SigLIP2. It helps only as a second opinion on the shortlist, with the stage-one scores kept.

Known failure modes

  • The descriptor can describe what should change. For the BMW query below, the descriptor mentions the bike's white body while the edit asks for black.
  • Context-dependent identities. Signs, beaches and landmarks depend on viewpoint and surroundings that one descriptor line does not pin down.
  • Recall is capped by stage 1. A reranker only reorders the top 100; positives outside it (6.92% on average) cannot come back.
